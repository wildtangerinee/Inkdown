## 1. 技术栈与关键决策

| 领域 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | C++17 | 主语言；不默认使用 C++20 专属特性 |
| 桌面 UI | Qt 6 Widgets | 原生控件路线，不使用 Electron/WebView 作为编辑核心 |
| 初期文本视图 | `QTextEdit` / `QTextDocument` | 借助现成的排版、光标、选区、输入法能力 |
| 编辑命令 | `QTextCursor`，必要时统一命令层 | 局部编辑与格式控制 |
| 构建 | CMake | macOS + Windows |
| 测试 | Qt Test + CTest | 解析/序列化单测、编辑器集成测试 |
| 文件保存 | `QFile`、`QSaveFile` | 安全写盘 |
| 设置 | `QSettings` | 界面设置与最近文件等 |
| 代码检查 | clang-format、可选 clang-tidy | 渐进引入 |

**重要边界：** `QTextEdit` 可以渲染/编辑富文本，但**不自带完整 Typora 式 Markdown 即时编辑引擎**。`setMarkdown()` 等整体替换接口不能放入逐键编辑循环：整体重建会干扰光标、选择和撤销历史。

## 2. 先验证，后固化架构

当前优先执行 **M0 技术验证**，不能把下面的概念模型当作已经实现的事实。

- **M0 原型**：允许以 `QTextDocument` 作为临时可编辑状态，探索触发语法、光标位置、输入法、撤销行为及导出。
- **M1 个人可用首版**：通过 `QTextEdit` 直接编辑渲染后的普通段落、一级和二级标题、粗体及一层无序列表。只引入支撑这些格式的编辑和安全往返所需的模型与同步逻辑；通用位置映射、自动展开标记留到后续。
- **架构关口**：若 `QTextEdit` 的局部更新或行内标记显隐有实质性限制，先评估局部定制/自定义布局；仅在必要时考虑自绘编辑器。

## 4. 逻辑文档与视图

### 4.1 单一逻辑真相源

长期目标是：**文档源文本/语义模型负责持久化含义，`QTextDocument` 是可编辑的显示载体**。不能简单认为富文本样式足以无损表示 Markdown（例如标记选择、转义、未支持扩展）。

建议逻辑模型至少记录：

- Markdown 源文本和原始片段。
- 语法节点类型、属性、父子关系、稳定 ID（按需引入）。
- 源码范围和视图范围之间的映射。
- 修改范围、当前编辑事务、是否已保存。
- 未支持语法的原文保留状态。

节点示例：Document、Paragraph、Heading、Text、Strong、Emphasis、List、ListItem、Quote、CodeBlock、InlineCode、Link、Image、Table。

### 4.2 位置映射

`**Hello**` 在 Markdown 源码中占 9 个 ASCII 字符，在可视化视图中可能只显示 5 个可编辑字母；源码与视图偏移不能直接等同。

必须区分：

1. 文件字节偏移（UTF-8 字节）。
2. 文本内部的 Unicode 位置。
3. Qt 文本光标位置（通常按 UTF-16 代码单元计）。

Emoji、组合字符和换行会使这些偏移关系更复杂。位置映射应显式封装，不能到处做简单加减。

### 4.3 未支持语法

无法完整表达的结构应保留源码片段，首版优先按原文显示。无法确认安全往返时，应明确提示并阻止可能丢失内容的保存。

## 5. 输入到渲染的流程

```text
键盘 / 粘贴 / 删除 / IME 提交
          ↓
    Qt 编辑事件
          ↓
控制器确定本次受影响范围
          ↓
Parser 判断完整、合法的 Markdown 语法
          ↓
更新逻辑文档/语义节点
          ↓
QtEditorAdapter 局部修改 QTextDocument
          ↓
恢复正确的光标和选区，合并编辑事务
          ↓
更新 modified 标记
```

### 5.1 块级语法：输入 `# ` 或 `## `

- 条件：在允许标题语法的行首输入 `# ` 或 `## `。先验证一级标题，再扩展到二级。
- 创建对应级别的标题语义，保留隐藏标记表达的含义。
- 视图删除可见标记、设置标题块格式；光标位于标题内容起始。
- 回车后按照产品约定进入普通段落。
- 转换与随后输入的撤销行为需要实际测试，不能假设 Qt 自动满足。

### 5.2 行内语法：输入 `**hello**`

- 在闭合标记完整且不被转义的情况下识别。
- 模型保留 Strong 语义；视图将 `hello` 设为粗体并隐藏定界符。
- 允许在粗体文本中继续输入、选择或删除。
- 首版保持标记隐藏。光标进入区域时展开源码标记或提供等效编辑控件的实验留到后续。

### 5.3 列表：输入 `- `

- 识别一层无序列表项；优先使用 Qt 文本块/列表格式功能。
- 回车创建下一项；空列表项回车退出。
- 原文列表标记及缩进语义必须可正确序列化。

### 5.4 解析触发策略

- **普通输入**：仅检查当前段落及相关行内区间。
- **闭合字符/空格/回车**：检查特定触发规则。
- **删除/跨段落编辑**：扩大重解析范围以涵盖结构变化。
- **粘贴**：按粘贴范围解析，并对异常大的粘贴控制成本。
- **初次加载**：允许一次完整解析。

避免每按一次键解析和替换整个文档。

## 6. 光标、输入法与撤销重做

### 6.1 光标和选区

- 正式修改前记录逻辑位置（节点与局部偏移），修改后映射回视图位置。
- 批量格式化时尽量使用 `QTextCursor` 局部操作。
- 处理边界：段落首尾、嵌套格式、跨段落选择、换行与 Emoji。
- 格式标记显隐只应影响呈现；不应无故移动或丢失选区。

### 6.2 中文输入法（IME）

- 避免在预编辑（preedit）过程中对文本进行破坏性替换。
- 在输入提交（commit）后进行相关 Markdown 触发判断。
- 优先保持 QTextEdit 自有输入法处理，不随意截获全部键盘事件。
- 需要 macOS 中文拼音和后续 Windows 中文输入法手工验证。

### 6.3 撤销重做

- M0 先验证 Qt 原生 undo/redo 与 `QTextCursor::beginEditBlock()` / `endEditBlock()`。
- 正式逻辑模型不能和 QTextDocument 保留两份互相独立的撤销历史。
- 如果原生撤销无法可靠同步语义模型，改由统一编辑命令/事务层协调；可评估 `QUndoStack`，但不得简单叠加两套历史。
- 显示标记的展开/收起不能额外制造“用户可见的撤销步骤”。

**回归场景：** 格式转换→继续输入→多次撤销→重做→保存→重新打开；跨节点删除；复制粘贴；IME 后撤销。

## 7. 文件 I/O 和序列化

### 7.1 打开文件

1. `QFile` 读取原始字节。
2. 处理可选 UTF-8 BOM 并验证编码；不支持的编码应提示，不随意转换后覆盖。
3. 检测记录换行风格（LF/CRLF）。
4. 生成源文本与语义模型。
5. 构建显示视图，清除“已修改”状态。

### 7.2 保存文件

1. 结束编辑中的暂态，确认模型/视图一致性。
2. `MarkdownSerializer` 序列化。
3. 尽可能保留未修改片段的原文，修改片段输出规范 Markdown。
4. 处理换行策略和 UTF-8 编码。
5. 使用 `QSaveFile` 写入与 `commit()`，检查失败返回值。
6. 仅在成功后更新“已保存”状态。

不默认启用破坏原子性保证的直接写入回退。

### 7.3 一致性验证

- **无编辑往返**：打开→保存，不应凭空删除文本或不支持语法。
- **编辑后语义往返**：解析→编辑→序列化→再解析，支持语法的结构、内容相同。
- **混合文本**：中文、英文、Emoji、反斜线转义、空行、行尾换行。
- **文件异常**：无写权限、磁盘空间不足、路径不存在、外部修改。

Qt 的 `toMarkdown()` 可用于 M0 的能力探索和对照验证，但不承诺满足完整源码保真需求。

**T006 初测（Qt 6.10.1，默认 Markdown 方言）：** 将原型输入导出到临时 `.md` 再导入，一、二级标题、粗体、两项无序列表、中文、Emoji 和未闭合的 `**` 都保留了可见内容或格式含义；修改导入后的一级标题再往返，级别仍为 1。单独的空段落重开后被折叠。对现有源码直接导入再导出，`<kbd>Ctrl</kbd>` 变成普通 `Ctrl`，脚注示例被改写成链接。因此不能用这对 API 直接覆盖任意原始 Markdown 文件。

**覆盖保护实验：** 在临时文件中，用“导入后立即导出的 UTF-8 字节与原文件完全相同”作为覆盖保存的必要条件。`# One\n\n` 能编辑、写回并重开；`# One\n`、内嵌 HTML 和脚注样例均被拦截，原文件字节不变。这个检查会误拦只存在写法差异的文件，也不能保证后续编辑不会引入导出差异。它只验证了保守拦截的可行性；未实现不支持片段的原文显示或安全的正式保存流程。

## 8. 性能与线程

- GUI 控件仅在 GUI 线程更新。
- 默认局部重解析、局部格式更新，避免重建全文。
- 文件加载和解析在实际证明需要时再拆入工作线程；必须在 UI 线程安全地提交结果。
- 为 100KB 编辑响应和 1MB 加载建立可重复的基准测试，记录设备、Qt 版本和输入语料。
- 优先排除不必要的信号重入、全文重排和多余内存复制。

## 9. 测试策略

### 9.1 单元测试

- 常见块级/行内语法、非法或未闭合语法、转义和嵌套。
- Markdown 语义往返与未识别源码保留。
- 文档模型变更和位置映射。

### 9.2 编辑器集成测试

- `# `、`**text**`、`- ` 的触发与结果。
- 连续键入、退格、跨块选区、复制粘贴。
- 撤销/重做与源模型同步。
- 打开→编辑→保存→重新打开。

### 9.3 手工验证

- macOS 输入法、菜单快捷键和鼠标。
- 深浅色主题与高 DPI 显示。
- Windows 平台后续单独回归。

## 10. M0 技术门槛和降级路径

| 实验 | 最低通过条件 | 主要风险 |
| --- | --- | --- |
| V01 标题 | `# `、`## ` 转换、继续输入、回车正确 | 光标/块格式 |
| V02 粗体 | `**text**` 转换后可继续编辑 | 标记隐藏和格式继承 |
| V03 列表 | `- `、回车继续、空项退出 | QTextList 行为 |
| V04 撤销 | 连续撤销与重做不破坏内容 | 事务不一致 |
| V05 往返 | 标题/粗体/列表语义保持，未编辑且不支持的语法保留原文 | 序列化信息丢失 |
| V06 输入法 | 中文拼音输入、候选提交和混合输入正常 | 预编辑被错误转换 |

V07（行内标记展开实验）留到后续，不作为 M0 或个人可用首版的关口。

**决策树：**

1. 若 V01–V06 基本通过，继续基于 `QTextEdit` 开发。
2. 若 QTextEdit 的内部文档模型持续阻碍数据正确性，评估自定义布局/编辑适配层。
3. **完全自绘 QWidget 文本编辑器**为最后选项，因为排版、IME、辅助功能、选区成本非常高。

实验结论要记录在本文件的 ADR 区，不能把“技术上可实现”当作“已经实现”。

## 11. 风险登记

| 风险 | 等级 | 缓解方式 |
| --- | --- | --- |
| 源码与视图位置不同步 | 极高 | 专门映射层与 Unicode 测试 |
| 格式转换破坏撤销历史 | 极高 | M0 事务实验、统一命令模型 |
| 保存丢失未知语法 | 极高 | 原始片段保留、往返测试 |
| 中文输入法冲突 | 高 | commit 后转换、IME 手测 |
| 表格/图片复杂编辑 | 中高 | P1 独立评估 |
| 大文档重排与性能 | 中 | 局部更新、基准测试 |
| macOS/Windows 行为差异 | 中 | 平台分阶段测试 |

## 12. 架构决策记录（ADR）

- **ADR-001**：语言为 C++17。状态：已决定。
- **ADR-002**：GUI 采用 Qt 6 Widgets。状态：已决定。
- **ADR-003**：首先使用 QTextEdit 构建 M0 原型。状态：已决定，完整适用性待验证。
- **ADR-004**：以 `.md` 为主要持久化格式。状态：已决定。
- **ADR-005**：禁止在逐键输入循环中调用全量 `setMarkdown()` 重建文档。状态：已决定。
- **ADR-006**：M0 后根据验证结果确定首版所需的最小语义模型；自动展开标记留到后续。状态：模型待验证，首版范围已定。

**设计底线：编辑正确性 > 数据完整性风险之外的视觉炫技；绝不以静默丢内容换取即时渲染。**
