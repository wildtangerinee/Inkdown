## 1. 项目定位

**Inkdown** 是一款免费、开源、优先离线运行的原生桌面 Markdown 编辑器。核心价值是 **直接编辑已经渲染的内容**：用户不需要在 Markdown 源码区与预览区之间来回切换。

编辑体验参考 Typora，吸收 Notion 的简洁性，但不以复刻二者全部功能为目标。文档以普通 `.md` 文件为主，不依赖账号、云服务或专有格式。

### 1.1 目标用户

- 编写 README、技术文档、博客的开发者。
- 整理笔记、课程资料的学生与普通写作者。
- 想使用本地 Markdown 文件、偏好原生桌面应用的用户。

### 1.2 产品目标

1. 实现**单编辑区、所见即所得**的 Markdown 输入和修改。
2. 输入完整 Markdown 语法时即时转换，而不是每输入一个字符都重建整个文档。
3. 保证光标、选区、输入法、撤销重做稳定。
4. 打开和保存 `.md` 文件时不静默丢失内容。
5. 优先发布 macOS 版本，之后适配 Windows。
6. 主要使用 C++17 + Qt 6 Widgets 开发，核心逻辑具备测试。

### 1.3 个人可用首版

首版面向 macOS 本地笔记：在一个编辑区直接编辑渲染后的内容，新建、打开、保存和另存为本地 `.md`。格式仅支持普通段落、一级和二级标题、粗体及一层无序列表。后续功能不作为个人可用版的交付条件。

### 1.4 非目标

首个稳定版本不做云同步、多人协作、账号系统、移动端、AI 写作、插件商城、Notion 式数据库。后续是否增加这些功能另行讨论。

## 2. 核心编辑体验

### 2.1 即时转换原则

识别到**完整且有效**的语法后执行转换；不完整的输入保留为普通文本。默认不采用左右分栏实时预览。

| 输入示例 | 触发时机 | 期望显示/行为 | 优先级 |
| --- | --- | --- | --- |
| `# ` | 行首输入空格后 | 一级标题，继续直接输入标题 | P0 |
| `## ` | 行首输入空格后 | 二级标题，继续直接输入标题 | P0 |
| `**hello**` | 最后一个 `*` 输入后 | 加粗 `hello` | P0 |
| `- ` | 行首空格后 | 无序列表项 | P0 |

**说明：** `P0` 为个人可用首版必需，`P1` 为后续候选。输入在代码块、转义序列或其他不适用语境中时，不应被错误转换。

### 2.2 标记显隐

首版隐藏已渲染的标题、列表和粗体标记，允许直接修改文字，并保留对应的 Markdown 语义。光标进入时自动展开标记、独立的格式修改控件留到后续。

### 2.3 必须正确的编辑行为

- 在已渲染的标题、粗体、列表内直接编辑文字。
- 使用鼠标点击、方向键、Home/End、Shift 选择文本。
- 复制、剪切、粘贴；支持普通文本粘贴。
- 回车后：标题创建普通段落；列表继续下一项；空列表项回车退出列表。
- Backspace/Delete 跨越格式边界时语义一致。
- 中文输入法（包括候选/组合输入）不被即时转换打断。
- 撤销/重做顺序符合用户预期；保存前后状态一致。
- 未被识别的 Markdown 语法可保留原文，不因编辑或保存消失。

## 3. 功能范围

### F01. 本地文件（P0）

- 新建、打开、保存、另存为 `.md` 文档。
- 未保存标记；关闭有修改的文档时询问。
- UTF-8 文件、可选 BOM 和 LF/CRLF 换行处理。
- 文件写入采用安全保存机制；保存失败不能覆盖损坏原文件。
- 拖拽打开、最近文件属于 P1。

### F02. 所见即所得编辑器（P0）

- 单编辑区、可直接编辑渲染内容。
- 标题、段落、粗体、列表的即时转换。
- 基础光标、选区、撤销重做与输入法支持。
- Markdown 语义与富文本视图保持一致。

### F03. Markdown 核心语法（P0/P1）

P0：普通段落、一级和二级标题、粗体、一层无序列表。

P1 候选：行内代码优先考虑；其余包括三级至六级标题、斜体、引用、有序列表、删除线、围栏代码块、链接、水平线、任务列表、图片、表格、嵌套列表和代码高亮。

以 CommonMark 的常用语法为基础，逐步支持 GitHub Flavored Markdown 常用扩展；首版不宣称 100% 兼容两者。

### F04. 日常编辑辅助（P1）

- 查找与替换。
- 文档大纲（依据标题）。
- 字数、行数与保存状态。
- 多文档标签页、最近文件。
- 浅色/深色主题、字体及编辑宽度设置。
- Markdown 源码模式，用来查看和编辑不支持的语法。

### F05. 数据完整性（P0）

- 打开、编辑、保存、重新打开之后，已支持 Markdown 的**语义**不变。
- 对未编辑且可保留的源码片段，尽量保留原始写法。
- 对未支持语法不得静默清除；无法保证编辑安全时保留源码或明确提示。
- 外部文件修改冲突检测属于 P1，不允许无提示覆盖。

## 4. UI 与交互设计（合并原 UI_DESIGN）

### 4.1 信息架构

- **顶部**：系统菜单、可选文档标签页。
- **中央**：居中、可滚动的 Markdown 编辑区域，默认无额外预览分栏。
- **左侧**：可折叠的标题大纲（P1）。
- **底部**：轻量状态栏（字数、保存状态等，P1）。

### 4.2 视觉原则

- 以正文排版为主，避免大量工具栏与按钮抢占空间。
- 标题层级和列表缩进应清晰。
- 主题颜色和显示字体不改变保存的 Markdown。
- 遵循平台习惯：macOS 使用 Command 快捷键，Windows 使用 Ctrl 快捷键。
- 优先使用 Qt Widgets 原生能力；不要为“看起来像网页”而引入 WebView。

### 4.3 关键状态与反馈

- 无文档、正常编辑、文件未保存、保存失败、文件外部修改分别有可理解的提示。
- 格式转换不弹出提示，不打断流畅输入。
- 未识别或不完整语法保持可编辑原文。
- 打开不支持编码、不可写路径、文件权限失败时显示明确错误。

## 5. 非功能要求

| 维度 | 目标 |
| --- | --- |
| 平台 | macOS 首发；Windows 后续适配 |
| 离线 | 不依赖网络即可完成主要编辑功能 |
| 响应 | 100KB 文档连续输入，编辑响应 P95 参考目标 ≤50ms（指定测试设备，实际测量） |
| 加载 | 1MB 常规 Markdown 文档加载参考目标 ≤2s（指定测试设备，实际测量） |
| 稳定性 | 无已知高优先级数据丢失、崩溃和基本输入法缺陷 |
| 可维护性 | 解析/序列化可独立测试，UI 与核心逻辑解耦 |

性能数字是**待测目标**，不是对当前产品的承诺。

## 6. 版本里程碑

- **M0 技术验证**：证明 QTextEdit 可以处理标题、粗体、列表即时转换及基本撤销、往返和中文输入。
- **M1 个人可用首版**：本地文件读写、最小模型和 P0 编辑能力。
- **M2 编辑核心**：稳定的 Markdown 语义同步、标记编辑、更多语法与回归测试。
- **M3 应用完善**：P1 UI、图片、表格等功能。
- **M4 发布**：性能、兼容性、打包、文档与首次 macOS 稳定版；之后移植 Windows。

## 7. 个人可用首版验收标准

1. 新建、打开、编辑、保存、另存为和重新打开 `.md` 正常；关闭有未保存修改的文档时提醒。
2. `# `、`## `、`**text**`、`- ` 即时转换可用，已渲染内容可直接修改，保存重开后格式和内容保持正确。
3. 光标、选区、撤销重做、中文输入法的核心操作稳定。
4. 不支持的 Markdown 语法不会被无提示删除。
5. 文件保存失败时不损坏原文件。
6. 主要 Markdown 语法有自动测试；编辑核心有手工回归清单。
7. 无网络条件下工作正常。
8. 在本机 macOS 上可构建并运行。安装包和干净环境验证留到 M4。

## 8. 开放问题

- 行内语法在光标进入时展开**原始标记**，还是通过轻量交互编辑：后续按需验证。
- 首次稳定版表格的编辑深度：待基础编辑模型稳定后确定。
- Markdown 解析是否采用成熟第三方库：以数据保留、许可和集成成本评估。
- 开源许可证：公开发布前确认，勿在未经选择时假设已授权。
